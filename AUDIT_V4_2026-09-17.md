# PArAsYtE Browser v0.3 Audit - 17 September 2026

## Release-blocking faults addressed

- **YouTube / anti-frame sites:** desktop browsing moved from iframe rendering
  to native Electron `WebContentsView` tabs. The hosted web app retains a safe
  fallback and explains when a destination needs the desktop browser.
- **New tabs:** the chrome now owns real independent tab state. `+`,
  Cmd/Ctrl+T and links using `target=_blank` create PArAsYtE tabs; tabs can be
  switched, closed, and the last closed page can be reopened with
  Cmd/Ctrl+Shift+T.
- **Bookmarks:** replaced the warning-only sidebar action with a usable saved
  sites library and bookmark toggle.
- **Downloads:** desktop downloads now have an in-app activity page with
  progress, open, and show-in-folder actions. The hosted build clearly states
  that the host browser owns downloads.
- **Extensions:** removed the misleading sidebar entry until PArAsYtE has a
  genuine extension engine/security model.
- **Duplicate macOS controls:** removed the decorative in-app traffic lights.
  The native title bar is the single minimize/maximize/close control surface.
- **Appearance:** size, glow, wallpaper, sidebar mode and system/light/dark
  controls use the shared appearance state and persist locally.
- **Dead auth controls:** removed the fake SSO button and replaced the fake
  “Remember me” checkbox with truthful secure-session status.

## Security findings and changes

- Guest tabs run with Node integration disabled, context isolation and sandbox
  enabled.
- Guest permissions are denied by default.
- Private/local literal hosts are blocked in both navigation and subresource
  requests.
- New-window requests are captured and routed into controlled PArAsYtE tabs.
- External mail/tel/sms protocols are delegated to the OS.
- No response-header stripping was added to make sites load.
- Guest web contents are explicitly closed when their tab/window is closed.

### Remaining security work

- Add DNS resolution/rebinding protection; literal-host filtering cannot catch
  every hostname that resolves to a private address after DNS resolution.
- Move the desktop runtime to a currently supported Electron release before
  distributing installers. Electron 33 in the received lockfile is obsolete.
- Decide whether account avatars/wallpapers should remain in a public-read
  storage bucket or move to signed/private delivery before marketing them as
  private account media.
- Add a dedicated permission prompt/allow-list design before enabling camera,
  microphone, location, notifications, USB/Bluetooth, clipboard-read or MIDI.

## Product audit

The desktop application is now a browser shell rather than an iframe demo, but
it should not claim parity with Brave/Chrome yet. PArAsYtE's current shield UI
reports connection/session/trust state; it is **not** a full tracker/ad-blocking
network engine.

Highest-value next work:

1. vertical tabs with collapse, pinning and groups
2. split view implemented with two simultaneous `WebContentsView`s
3. explicit Personal/Work/Banking/Temporary containers using isolated Electron
   session partitions
4. reader mode and translation
5. encrypted cross-device sync
6. privacy/network controls with auditable block lists
7. extension compatibility only after permissions, signing/provenance and
   process isolation are designed
